# ระบบหลัก (main.py) + ระบบตัวแทน (agent_app.py) + common.py

## ไฟล์ (วางไว้ในโฟลเดอร์เดียวกันของแต่ละระบบ)
- `main.py` — ระบบหลักฉบับแพตช์ **ไฟล์เดียวพร้อมใช้ แทนไฟล์เดิมได้ทั้งไฟล์** (ใช้ session cookie แทน `?user=`)
- `agent_app.py` — ระบบตัวแทนฉบับเต็ม
- `common.py` — โมดูลกลาง **ทั้งสองระบบต้อง import** (ต้องเป็นไฟล์เดียวกัน / เวอร์ชันเดียวกัน)
- `requirements.txt`

## ขั้นตอน
1. **สำรองฐานข้อมูลก่อน** (migration จะลบแถวซ้ำใน `CustomerLottoRates` และ `DrawResults` ที่งวดซ้ำ แล้วสร้าง unique index)
2. แทนที่ `main.py` เดิมด้วยไฟล์ใหม่ และวาง `common.py` ไว้ข้างๆ (ทั้งสองระบบ)
3. ตั้ง environment variable (ทั้งสองระบบ):

| ตัวแปร | ความหมาย |
|---|---|
| `DB_URI` | บังคับ — รหัสผ่านใหม่ (รหัสเดิมเคยอยู่ในโค้ด ให้เปลี่ยน) |
| `SECRET_KEY` | บังคับให้ **เหมือนกันทั้งสองระบบ** ถ้าอยากให้ล็อกอินครั้งเดียวใช้ได้ทั้งคู่ (คุกกี้ใช้ร่วมกันได้เมื่ออยู่โดเมน/โฮสต์เดียวกัน แม้ต่างพอร์ต) |
| `COOKIE_SECURE` | `1` เมื่อรันหลัง HTTPS |
| `HASH_PASSWORDS` | `1` = เก็บรหัสแบบแฮช เปิดได้เมื่อ **ทั้งสองระบบ** เป็นไฟล์ชุดใหม่นี้แล้ว (ใช้ `verify_password` ทั้งคู่) รหัสเก่าที่ยังเป็นข้อความธรรมดายังล็อกอินได้ |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | สร้างแอดมินแรกเมื่อตาราง Users ว่าง |
| `RUN_MIGRATIONS` | ค่าเริ่มต้น 1 |

4. รีสตาร์ทระบบ แล้วทดสอบตามรายการด้านล่าง

## main.py ใหม่ทำอะไรเพิ่ม/ต่างจากเดิม
- **Session**: middleware ตรวจคุกกี้ทุกหน้า (ยกเว้น `/login`, `/logout`, `/`) และ **เขียนทับ `user`/`username` ด้วยชื่อจาก session** — แก้ URL เป็น `?user=admin` ไม่ได้ผลแล้ว; ลิงก์เดิมที่มี `?user=` ยังทำงาน
- **สิทธิ์ตามบทบาท**: หน้าเลขอั้น/ผลรางวัล/audit/db-inspector/รีเซ็ตระบบ = Admin เท่านั้น; จัดการผู้ใช้ = ระดับผู้จัดการ; สร้างผู้ใช้ได้เฉพาะระดับที่ต่ำกว่า
- **กัน CSRF พื้นฐาน**: ปฏิเสธคำขอ cross-site (POST และลิงก์ลบ/ปิดงวดแบบ GET) ผ่านหัว `Sec-Fetch-Site`
- โพยร่างผูก `lotto_name` + `draw_date`; ส่วนลดเก็บเป็นบาท; ใช้เรตแยกหวยจาก `common.get_rates`
- ออกบิล: ล็อกแถวโพยร่าง, เช็คงวด/เวลาปิดรับ/เลขปิดรับฝั่งเซิร์ฟเวอร์, เลขบิลจาก `common.generate_bill_no`, rollback เมื่อพลาด
- ล็อกอินล็อก 5 ครั้งรอ 5 นาที, Jinja autoescape เปิด, URL ที่มีชื่อหวย (เช่น `S&P 500`) ถูก encode
- `except: pass` ถูกเปลี่ยนเป็นแสดงข้อผิดพลาดและบันทึก log
- ฟอร์มลูกค้า/ผู้ใช้เพิ่มช่อง "จ่าย 3โต๊ด" และหน้าเรตแยกหวยเพิ่ม "ส่วนลดวิ่ง"
- ลบ route `system-reset` ที่ซ้ำกันสองชุดเหลือชุดเดียว; ปุ่มรีเซ็ตแสดงเฉพาะ Admin

## รายการทดสอบหลังติดตั้ง
1. เปิดหน้าใดๆ โดยไม่ล็อกอิน → เด้งไป `/login`
2. ล็อกอินด้วยสมาชิกทั่วไป แล้วลองแก้ URL เป็น `?user=admin` → ยังเป็นสมาชิกเดิม
3. สมาชิกทั่วไปเปิด `/results`, `/blocked-numbers` → ถูกปฏิเสธ
4. เพิ่มโพย → ออกบิล → ดูใน `/reports` และในระบบตัวแทน (`/agent-reports`) ต้องเห็นบิลเดียวกัน
5. ลองกับหวยที่ชื่อมี `&`

## ข้อจำกัดที่ควรรู้
- ยังไม่ได้ทดสอบกับฐานข้อมูลจริง (สภาพแวดล้อมนี้ไม่มี Postgres/เครือข่าย) — ทดสอบแล้ว: compile, ไม่มีชื่อที่ไม่ได้นิยาม, parse เทมเพลตทุกหน้า, middleware, และ flow เพิ่มโพย→ออกบิลกับฐานข้อมูลจำลอง **ให้ลองกับสำเนาฐานข้อมูลก่อน**
- `DrawResults` / หน้า `/results` ยังอ้างอิงตามวันที่งวดเท่านั้น (ไม่แยกตามชื่อหวย) ตามโครงสร้างเดิม
- ลิงก์ลบ/ปิดงวดบางจุดยังเป็น GET (ป้องกันด้วยการตรวจ cross-site เท่านั้น)


## ฟีเจอร์ใหม่ (รอบล่าสุด)
- **หน้าเลือกงวด** (ระบบหลัก `/campaigns`, ระบบตัวแทน `/select-market`): การ์ดสีเขียว = เปิดรับ, สีขาว = ปิดรับ/ยังไม่ถึงเวลาเปิด, นับถอยหลังสด, เรียงตามเวลาที่เหลือน้อยสุดก่อน, สลับมุมมอง "แยกกลุ่มหวย" (รัฐบาล / ลาว / ฮานอย / หุ้นต่างประเทศ / หุ้น VIP / อื่นๆ), มีตัวเลือกแสดงงวดที่ปิดแล้ว
- **สร้าง/แก้ไขงวด**: กำหนด "เวลาเปิดรับ" และ "เวลาปิดรับ" ระบบเปิด-ปิดรับให้อัตโนมัติตามเวลา (ตรวจฝั่งเซิร์ฟเวอร์ทุกครั้งที่บันทึกโพย/ออกบิล) ปุ่ม "เปิด/ปิดงวด" ยังใช้ปิดเองด้วยมือได้ (คอลัมน์ใหม่ `open_time` สร้างให้อัตโนมัติตอนสตาร์ต)
- **สิทธิ์เรต/ส่วนลด**: ตั้งได้เฉพาะ "ลูกค้าที่ตัวเองสร้าง" และ "ผู้ใช้ที่ตัวเองเป็น upline โดยตรง" ตั้งให้ตัวเองไม่ได้ (รวมแอดมิน) และตั้งให้ใครก็ไม่ได้เกินเรต/ส่วนลดที่ตัวเองได้รับ (แอดมินเป็นต้นสาย ไม่มีเพดาน) ใช้กับ: ลูกค้า, ผู้ใช้, เรตแยกหวย ทั้งสองระบบ
- **ยอดขายสด (แอดมิน)** เมนู "📈 ยอดขายสด" ทั้งสองระบบ: รีเฟรชทุก 5 วินาที เลือกช่วงข้อมูล (ทุกงวด/วันนี้/งวดใดงวดหนึ่ง) แยกลูกค้ากับสายงาน ดับเบิลคลิกแถวสายงานเพื่อเจาะลึกลงไปทีละชั้น และมีเส้นทางย้อนกลับด้านบน ยอดรวมแต่ละชั้นรวมยอดทั้งสายของบัญชีนั้น (ไม่นับซ้ำ)

หมายเหตุ: ชื่อหวยที่ตั้งไว้ต้องตรงกับชื่อจริงของงวด การจัดกลุ่มใช้คำในชื่อ (เช่น "รัฐบาล", "ลาว", "ฮานอย", "VIP", ชื่อประเทศ/หุ้น)

## เมนูแอดมินในระบบตัวแทน (รอบล่าสุด)
แอดมินที่ล็อกอินระบบตัวแทนใช้เมนูได้เหมือนระบบหลัก: 📌 จัดการงวด (สร้าง/แก้ไข/เปิด-ปิด + เวลาเปิด-ปิดรับ), 🚫 เลขอั้น, 🏆 ผลรางวัล, 📊 แดชบอร์ด, 🔍 ตรวจสอบทั้งหมด/ส่วนลด, 🗄️ ตรวจสอบ DB, ⚠️ รีเซ็ตระบบ, 📈 ยอดขายสด
- เมนูที่ต้องเลือกงวด (เลขอั้น/ผลรางวัล/ตรวจสอบ) ถ้ายังไม่ได้เลือกจะแสดงการ์ดให้เลือกงวดก่อน
